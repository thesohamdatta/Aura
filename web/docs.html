Introduction

AURA is an open-source wearable AI context engine designed to continuously stream environment signals. It captures audio and visual frames, processing them into a searchable semantic memory locally or on self-hosted instances.

This documentation outlines how to build the pendant, configure the firmware, setup the multi-threaded RAG backend, and run the client applications.

Quick Start

To get a development environment running immediately, clone the repository and launch the backend using Docker Compose.

git clone https://github.com/thesohamdatta/aura.git
cd aura/backend
cp .env.template .env
docker-compose up --build

Bill of Materials

All hardware parts are off-the-shelf components. The total build cost is ~$60 USD (measured).

Part Name Specification Status
Microcontroller Seeed Studio XIAO ESP32-S3 Sense Specified
Camera OV2640 2MP (1600x1200 resolution) Specified
Microphone Digital PDM Microphone Specified
Battery 350mAh LiPo Battery (gives 1–2 hours of battery life, measured) Measured
Enclosure 3D-Printable PLA/PETG filament Measured

Assembly Guide

Assemble the hardware stack by connecting the LiPo battery directly to the battery pads on the underside of the XIAO module. Solder wire connections carefully to ensure structural rigidity.

Align the OV2640 camera ribbon cable into the FPC connector and lock it down. Mount the ESP32-S3 module inside the enclosure base, positioning the camera lens through the front bezel circular opening.

Enclosure

The CAD enclosure files are open-source and ready for printing. We recommend printing with PLA or PETG at a 0.2mm layer height with 15% infill. Magnetic clasp slots are integrated into the rear shell to secure the pendant during use.

Setup (Firmware)

Before compiling, configure the local credentials in the firmware code. Open firmware/main.cpp and configure the Wi-Fi credentials:

const char* ssid = "YOUR_WIFI_SSID";
const char* password = "YOUR_WIFI_PASSWORD";
const char* serverUrl = "ws://your-backend-ip:8000/stream";

Camera Configuration

Configure the OV2640 camera registers for optimized frame transfer. The default streams JPEG frames at 640x480 resolution (specified) over WebSocket streams at a target rate of 5 frames per second (measured).

Audio Configuration

The digital PDM microphone streams 16kHz mono audio (specified) over binary WebSocket channels. Audio data is packed into PDM chunks and sent directly to the Deepgram pipeline for transcription.

BLE Protocol

Bluetooth Low Energy (BLE 5.0) is configured to handle local device settings, device provisioning (Wi-Fi credential passing), and connection statuses. Device advertises itself as AURA-DEVICE-XXXX.

Installation (Backend)

The RAG backend is written in Python (FastAPI). Install the local dependencies using pip:

cd backend
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000

API Keys

The pipeline relies on cloud endpoints. Fill in the required API keys inside your .env file:

DEEPGRAM_API_KEY=your_deepgram_key
PINECONE_API_KEY=your_pinecone_key
OPENAI_API_KEY=your_openai_key
GROQ_API_KEY=your_groq_key

Endpoints

Core backend API endpoints exposed for streaming and querying:

Endpoint Method Description
/stream WS Websocket channel for incoming visual and audio streams from ESP32.
/query POST Submit user query to search the vector memory database.
/memories GET List indexed conversational memories.

iOS Setup

Open the Swift-based iOS app in Xcode. Configure the backend URL in Config.swift, sign with your Apple developer account, and build the target on an iOS device.

Android Setup

Open the Android project located in app/android/ inside Android Studio. Update local IP settings in the Gradle files and build the project to run on Android 12+ targets.

Note: No formal user studies have been conducted. Testing is limited to local developer instances.

How to Contribute

Contributions are welcome! Please fork the repository, commit clean changes inside feature branches, and submit pull requests. Check CONTRIBUTING.md in the repository root for design guidelines.
